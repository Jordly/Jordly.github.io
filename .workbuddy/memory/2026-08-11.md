## 5. 组别下拉右侧边框缺失（二轮修复，commit 45b8cb1）
- 第一轮（f30183a）加 `border-right:1.5px solid #475569` 无效：**CSS border 只影响 select 闭合框，管不到浏览器原生绘制的展开面板**
- 根因确认：Chrome/Edge on Windows 已知渲染 bug —— `appearance:none` 的 `<select>` 展开面板右侧（有时底部）边框缺失
- 最终方案：`pf-group-select` 恢复 `appearance:auto`（浏览器原生绘制面板，四边边框自动完整），同时 `background-image:none`（避免与原生箭头重叠）、`background:#fff`、`border:1px solid #475569`
- 经验：**要自定义 select 面板外观只能换 div 下拉**；纯 CSS 无法给原生 select 展开面板加边框。用户嫌自定义下拉复杂，选原生绘制兜底

## 6. 组别下拉最终修复（commit 1348f4a）——纠正方向错误
- **用户明确反馈**：前两版都做错了。要求（1）组别外框与月份/项目/类型**完全一致**（极光青绿色），不能单独改成黑色；（2）下拉展开后的选项面板边框要修复
- **纠正思路**：对比"项目"展开截图，发现 `.fb-select` 本身不破坏展开面板，问题在布局——`flex:1;min-width:0` 把"组别"压到仅文字宽度，触发 Chrome 渲染 bug
- **正确改法**：只调布局，不动外观/appearance/border/background
  ```css
  .pf-group-select {
    flex: none !important;
    width: 120px !important;
    border-radius: 5px !important;
    overflow: visible !important;
  }
  ```
  闭合外框完全沿用 `.fb-select`（青绿边框+渐变+青绿箭头），与"项目"一致；固定宽度 120px + 小圆角 + overflow visible 让展开面板四边完整
- **教训**：用户报"右侧缺框"时，先对比**同类元素**（如"项目"）确认到底是样式问题还是布局问题；不要急于改 appearance/border 这类会破坏视觉一致性的属性
