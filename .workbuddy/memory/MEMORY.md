## 🔒 权限管理系统（2026-07-02 优化）

### 角色系统
- ROLES改为动态系统，从localStorage加载（key: `chansee_roles`）
- 内置角色6个：超级管理员、管理员、客服总监、客服经理、客服主管、项目伙伴（不可删除）
- 支持自定义角色：新增、编辑、删除

### 权限配置
- 权限数据存储在localStorage（key: `chansee_permissions`）
- 每个角色对每个模块有7个操作权限：visible（可见）、view（查看）、edit（编辑）、import（导入）、export（导出）、manage（管理）、scope（数据范围）
- 不支持的操作会完全隐藏（不是禁用）

### 前端权限拦截
- 登录成功后自动调用`filterNavByPermissions()`过滤导航菜单
- `renderModule()`函数开头检查权限，无权限则跳转第一个有权限的模块
- 辅助函数：`hasPermission(module, action)`、`canViewModule(module)`

### 角色管理功能
- 新增角色：点击"＋"按钮，输入角色名称
- 编辑角色：hover角色项，点击"✏️"（仅自定义角色）
- 删除角色：hover角色项，点击"🗑️"（仅自定义角色），显示受影响用户
- 复制权限：点击"📋从其他角色复制权限"按钮

### 受影响用户提示
- 修改角色权限时，显示"此修改将影响X个用户"
- 删除角色时，提示用户角色将被设置为"项目伙伴"

## 🛡️ 数据安全铁律（2026-08-06 建立）

**代码中只允许放置演示用的假数据（Mock数据），所有真实数据必须仅存于浏览器 localStorage，绝不可硬编码写入代码内部。**

具体规则：
1. 所有 `DEFAULT_*` 或 `*_DATA` 开头的硬编码数组（如 GROUPS_DATA、ASSESSMENTS_DATA、DEFAULT_PROJECTS 等）只能包含虚构的演示数据，用于新用户首次打开时填充界面
2. 包含真实客户姓名、手机号、金额、员工信息的**任何内容**都不得写入代码文件
3. 系统正式投入运行时，所有数据通过手动输入或导入功能进入 localStorage，不通过修改代码载入
4. GitHub 仓库（Jordly.github.io）为公开仓库，全世界可见。违反此铁律 = 数据泄露事故
5. 每次修改代码前，大模型必须自查：是否在代码中引入了真实数据？有则立即停止并告知用户

## 📐 代码治理铁律（2026-08-06 建立）

1. **app.js 头部有代码地图**（注释形式），新增模块/函数时必须同步更新地图
2. **新功能必须写成独立函数挂到全局命名空间**（function xxx(){}），不得在已有函数中间硬塞代码
3. **每个业务模块前有分隔注释**（`/* ═══ 模块名 ═══ */`），新增模块必须加分隔标记
4. 拆分文件暂不执行，等"新增功能频繁出错"成为真实痛点时再启动
