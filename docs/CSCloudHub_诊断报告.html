二、问题清单（按优先级）

P0 严重 · 立即修复

① 全局函数 sel 被覆盖 → “问题管理”筛选栏 JS 崩溃

现象modules/issue.js:34 定义 sel(name,options,allLabel)（旧签名 3 参数）；modules/roster.js:305 后加载，定义 sel(id,label,opts,val,onch)（新签名 5 参数）并覆盖前者。
风险页面所有函数裸挂在全局（无任何 IIFE 包裹）。运行时 issue.js 调用 sel('status', arr, '状态') 实际走到 roster 版 → 对字符串 opts 调用 .map() 抛 opts.map is not a function，“问题管理”模块的筛选下拉框直接报错/空白。
建议两个 sel 改名区分（如 issueSel / rosterSel），或抽成单一带命名空间的工具 window.UI.select(...)，从根本上消灭全局覆盖。
证据：index.html 加载顺序中 roster.js(19) 晚于 issue.js(10)；全 19 个 JS 文件均无 IIFE 包裹，函数 100% 暴露全局。

② canViewModule 双定义，权限判断“靠加载顺序巧合”生效

现象app.js:2615 版：visible===true && view===true（严格）；modules/assessment.js:792 版：hasPermission(module,'visible')（只看 visible，宽松）。当前 app.js 排第 22 位覆盖了 assessment.js，线上走的是严格版。
风险一旦未来调整 index.html 脚本顺序、或合并/拆分文件，严格版就会被宽松版覆盖 → 没有“查看”权限的用户也能看到模块，**演变成权限漏洞**。这是个“定时炸弹”，不是已发生的事故。
建议删除 assessment.js 的重复定义，全系统只保留 app.js 的 canViewModule；并把 getPermission(app.js) 与 hasPermission(assessment.js) 收敛为单一权限接口。
证据：app.js 用 getPermission，assessment.js 用 hasPermission，两套“取权限”接口分散两处，canViewModule 调用方混用。
P1 重要 · 近期优化

③ 部署流程脆弱：双份文件 + 手动版本号，已漏同步 2 次

现象每次改文件需手动 cp 到 docs/ + 改两处 index.html 的 ?v=。当前存在 11 种不同版本号字符串（如 20260807-fix2、20260814-roster-v9…）。历史上 v6、v7 两次都漏复制 docs 副本，导致线上“改了不生效”。
风险强刷后仍看不到改动，反复返工排查，消耗大量时间。根因是“人肉双份维护”，必错。
建议① 用单一构建号（如 ?v=20260814）替代各文件独立版本号；② 写一个小脚本自动同步 docs + 自动 bump；③ 长期上 CI（git push 即部署）。

④ exportSystemData 双定义且语义完全不同

现象assessment.js:831 = 导出全部 chansee_ 前缀 localStorage（全量备份）；systemData.js:781 = 导出具体业务表（中文文件名）。systemData.js(23) 后加载覆盖 assessment.js(17)。
风险若“导出全部备份”按钮调用 exportSystemData，会误走到“导出业务表”逻辑，备份可能不完整/错位。
建议按用途改名（exportAllBackup / exportBizTables），彻底避免同名冲突。

⑤ 权限逻辑分散 + localStorage 数据单点风险

现象取权限接口分两处（getPermission / hasPermission）；所有业务数据仅存浏览器 localStorage，清除 Cookie/换设备即丢失，云端同步靠手动触发。
风险① 权限逻辑易漂移、改一处漏一处；② 误操作清缓存 = 数据全丢，无本地兜底。
建议① 收敛权限为 permissions.js 单一服务；② 关键操作前引导“先云同步”，确保 backupAllData（core-security 已具备）入口显眼，登录/退出页加自动云同步。

五、术语大白话解释

全局函数覆盖：所有 .js 文件的函数都直接挂在“窗口”上，没有 namespace（命名空间）。两个文件写了同名函数，后加载的会把先加载的“冲掉”——后写的赢。这是本次 P0 两个 Bug 的根因。

IIFE：一种“把代码包起来不让外面看到”的写法 (function(){ ... })()。用了它，内部函数就不会污染全局。当前 19 个文件都没用。

XSS：黑客往页面塞恶意脚本。本项目用 esc/escHtml 把用户输入“转义”成纯文本来防。已普遍使用，但建议做一次全面审计确认无遗漏。

localStorage：浏览器自带的“小数据库”，关网页数据还在，但清缓存/Cookie 会清空。当前系统所有业务数据存这里，所以清缓存 = 数据丢（除非已云同步）。

版本号（?v=）：浏览器会缓存 js/css。改了代码必须改版本号，用户强刷才能看到新内容。当前每个文件版本号独立手动维护，易漏。
